# Mudra Relational Map

A short reference for what each gesture in the installation does, what it means, and what it does not claim.

## The two recognized gestures

### Chin mudra (one hand)

**Form:** thumb tip and index finger tip touching, other three fingers extended.

**In the installation:** when the system detects Chin mudra held for ~2 seconds, the dream cloud collapses inward — every dream-fish converges to a single point near the mudra-ing hand, then breathes outward again as the gesture is released.

**What it expresses:** *all my relations.* The Lakota phrase *Mitakuye Oyasin* — recognition that no being stands apart, that what we call individual is already a node in a web of kin.

**What it does not claim:** Chin mudra in this installation does not claim to perform any traditional or ceremonial function. The gesture is borrowed from yogic tradition as a public, well-known gesture; the installation's response (cloud-collapse) is an aesthetic mapping, not a ritual claim.

### Hakini mudra (two hands)

**Form:** all five fingertips of one hand touching the matching fingertips of the other hand, hands held a few centimeters apart at chest level. The thumbs touch. The fingers form a vault.

**In the installation:** when two visitors face each other and form Hakini together — or when one visitor forms it solo — the dream cloud reorganizes over ~6 seconds into the shape of a herring. Warm-colored dreams flow into the tail and dorsal stripe; cool blues fill the body; greens settle on the fins. The dreams remain themselves — color, position, and identity preserved within the new arrangement.

When the hands part, the dreams disperse and the cloud breathes again.

**What it expresses:** sympoiesis — making-with. The recognition that a coherent body (a herring, a forest, a Salish Sea) can briefly emerge from many small lives without consuming them. Hakini is the gesture of integration in tantric anatomy; in this installation, it is the gesture by which the field gathers as a body and then releases.

**What it does not claim:** the herring formation is not a verdict. It is a temporary holon — many dreams briefly appearing as one body. When the gesture ends, the holon ends. No data is stored. No interpretation is rendered. The dreams were never overwritten.

## What the system does and does not record

| Surface | Recorded? |
|---|---|
| Dream submission text | Yes (per consent toggles) |
| Dream embedding + cluster assignment | Yes (per consent toggles) |
| Mudra detection event | **No** — the gesture leaves no trace in any database |
| Cloud-collapse / herring formation | **No** — generated procedurally each time, never stored |
| Number of mudra events ever performed | **No** — uncountable by design |
| Which visitor performed a mudra | **No** — never identified |

The room is allowed to forget what the room did. The web remembers only what visitors asked it to remember.

## Other mudras the system does *not* recognize

This is intentional and worth naming:

- **Anjali mudra** (palms together at heart): not recognized. A widely-used greeting/prayer gesture across many traditions. Not implemented because the installation is not the right surface for that gesture's invocations.
- **Yoni mudra** (interlaced fingers, thumbs and pinkies extended): not recognized.
- **Padma mudra** (hands cupped like a lotus): not recognized.
- **Mudras specific to particular living traditions** (e.g. Buddhist Vajrayana, Hindu temple ritual, Indigenous gestural traditions of any nation): **not recognized, and would not be appropriate to implement** without the consent and authorship of the relevant tradition's stewards.

The system recognizes two well-known, widely-public hand positions and maps them to two visual responses. That is the whole gestural vocabulary.

## What happens when no mudra is detected

The default state of the cloud is: drifting, breathing, no special form. Dreams float. New dreams appear when visitors submit them. Old dreams age out only by visitor consent revocation, never by mechanical decay.

Visitors who do not perform any gesture see exactly the cloud. The mudra response is additive, not required.

## What the chat agent says when asked about a mudra event

If a visitor asks the chat agent *"what just happened?"* and the agent has reason to believe a recent mudra event occurred (a steward in the gallery has marked the event toggle), the agent answers in the four-shapes register:

> The system recognized four shapes at once: your hands, the code's threshold, the herring's ecological function, and the project's idea of making-with. The herring appeared because those shapes touched. The dreams were not overwritten; they briefly became a body together.

If no recent event is marked, the agent answers in Witness register without the four-shapes paragraph: *"I can describe what the system does when a gesture is recognized, but I don't have the room's recent context."*
