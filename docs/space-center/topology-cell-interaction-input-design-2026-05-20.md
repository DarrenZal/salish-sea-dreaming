## What This Document Updates

The parent doc (`cymatics-interaction-input-design-2026-05-20.md`) designed how input drives a cymatic field generically. Darren's latest direction sharpens that into a **topology-cell** model. This doc updates the input design accordingly and inherits, unchanged, the parent's Design Spine: the Cymatic Scene Parameter Vector (CSPV / `cymatic_scene.v1`) as the single renderer contract, the four-layer input model (Layer 0 clock, Layer 1 audio, Layer 2 visitor, Layer 3 operator), the conflict order operator > prompt > audio > clock, and the live/async split. It does not restate those - it changes only what the inputs build.

The topology-cell direction, restated for the input designer:

- **Render emergent overlap cells, not circles plus icons.** Seed-of-life and flower-of-life fields are generated by hex rings of construction circles, but the visible layer is the emergent primitive morphology those overlaps create. Construction circles are the hidden generator.
- **Center region = circle / origin.** The central one-boundary closed cell.
- **Two-arc lens / lune regions = crescents.** Pairwise circle overlaps.
- **Three-boundary outer scallop / triangular gap regions = curved trigons.** Three-circle gaps.
- **Radial growth = adding rings of construction circles over time** while still rendering mostly emergent crescents, trigons, and cells. One generator covers seed, flower, water ripple, sun, and snow through symmetry, timing, palette, and cell selection.
- **Snow becomes a rectangular falling-snow layer** made of many small topology snowflakes drifting down a rectangular frame - not one centered radial field.
- **Rain-on-water and nodal-plate outputs read as too crude.** v002 clips `02_rain_on_water_interference` and `04_cymatic_nodal_plate` are demoted from hero content - kept as internal reference, never centered. The strong v002 loops are `01_seed_of_life` and `03_snowflake_harmonic`.

Consequence for input design: every input now ultimately controls **how the circle-overlap arrangement is built and which emergent cells render** - origins, rings, symmetry, growth rate, cell selection, phase inversion, construction-circle opacity, and (for snow) the rectangular fall layer. All of it resolves into the CSPV before the renderer sees it. Raw prompt text, raw audio, and free-form input never reach the renderer.

## 1. How User Input Controls Topology-Cell Generation

Five input pathways. Each is a deterministic function into CSPV fields; none needs a model or the internet unless explicitly marked async.

### 1.1 Prompt -> mode

A web or voice prompt resolves, via the local keyword classifier (offline, live), to one of **five topology-cell modes**. Each mode is one generator configuration over the same overlap-cell extractor.

| Mode | Generator (`field_family` + `layout`) | Topology read | Notes |
|---|---|---|---|
| `seed` | `csg_seed`, `radial` | Center circle = origin; pairwise overlaps = crescent lenses/lunes; three-circle gaps = curved trigons. `ring_count` 1 reads as seed-of-life, 2+ as flower-of-life. | Hero mode. Flower-of-life is just `seed` with more rings. |
| `snow` | `csg_seed`, `rectangular_fall` | Many small sixfold seed-overlap units, each a self-contained circle/crescent/trigon cell cluster, drifting down a rectangular frame. | Rectangular falling layer, not a centered field. See 1.1.1. |
| `sun` | `bessel`, `radial` | Central orb = circle origin; concentric ring overlaps = crescent phase arcs; radial lobe gaps = trigon ray-release cells. | Abstract radial only - no exact Austin sun replication. |
| `water_ripple` | `multi_emitter`, `radial` | 3-7 ripple origins; overlap interference = crescent lenses + trigon gaps. | Gentle overlap-cell interference. Replaces the demoted crude rain-on-water clip. |
| `network` | `multi_emitter` -> nodal graph, `radial` | Intersection points = circle nodes; shared arcs = crescent edges; confluence gaps = trigon releases. | Sparse, faint, atmospheric. `mist` = low-energy preset of `network`. |

Mapping onto the parent CSPV enum: `seed` is a newly added `mode` value; `water_ripple` is the refined topology-cell renderer for the parent's `rain` (a legacy `rain` value is coerced to `water_ripple` behavior); `network` subsumes the parent's `mist`. The parent's `ocean`/`river` smooth-fluid water states remain valid and serve as base layers under a topology-cell layer (see scenario 3.1), but are not topology-cell hero modes.

#### 1.1.1 The snow rectangular-fall layer

Snow is the one mode that changes layout. `layout: rectangular_fall` tells the renderer to populate a rectangular frame with `snow.snow_depth` small snowflake units, each a mini seed-overlap topology cell cluster of internal symmetry `snow.flake_symmetry` (default 6). Units drift downward at `snow.fall_speed`; new units spawn at the top edge. This is distinct from the single centered radial field every other mode uses. The rectangular falling-snow layer is a recommended next render - it does not yet exist as a clip; today's offline fallback represents snow with the centered `03_snowflake_harmonic` v002 loop (see section 4).

### 1.2 Touch / click -> origin circle / new ring emitter

A visitor tap (or operator click) at normalized `(x, y)` appends one `impulse` to the CSPV with a `kind`:

```text
kind = "origin"  -> seed a new construction-circle origin at (x, y)
kind = "ring"    -> add one hex ring of construction circles to the nearest existing origin
kind = "ripple"  -> a damped-wave impulse (legacy water_ripple behavior, parent doc 2.4)
```

In topology-cell modes the default is `origin`; a tap near an existing origin promotes to `ring`. Either way the new construction geometry intersects the existing arrangement and **fresh crescents and trigons emerge at the new overlaps** - the visitor adds structure to the generator, not a stamped icon. Impulses carry `ttl_s` and expire; nothing a visitor adds is permanent. Rate limit inherited from the parent: max ~3 impulses/second, max 12 active, excess taps dropped not queued.

### 1.3 Audio amplitude -> ring growth rate / phase-inversion intensity

Continuous, Layer 1. Normalized audio RMS `a` in 0.0-1.0:

- `growth_rate = clamp(0.15 + 0.7 * a)` - how fast new rings of construction circles are added to the arrangement. Loud passages grow the field outward; quiet passages hold it.
- `phase_inversion_intensity = clamp(0.2 + 0.7 * a)` - how strongly the animation swaps between the outline/nodal phase and the filled-cell phase (the v002 phase-inversion model, grammar doc section 4A). Quiet keeps the field mostly in the calm outline phase; loud drives the full outline -> fill -> inverse-fill breath.

Smoothing stays where the parent put it: the bridge sends raw values, TouchDesigner smooths locally with a Lag/Filter CHOP (~0.3-0.6 s rise) so the field breathes rather than strobes. Phase inversion must never strobe (grammar doc 4A).

### 1.4 Frequency bands -> symmetry order / ring count / cell density

Layer 1, three-band split:

- **Low band** energy -> `ring_count` (0-5). Large, slow structural growth - how many hex rings of construction circles the arrangement carries.
- **Mid band** energy -> `symmetry_order` (0-8). The number of radial axes / overlap symmetry of the arrangement (fourfold, sixfold, eightfold).
- **High band** energy -> `density_cap` (8-24). Fine emergent-cell selection - how many trigon-release and crescent cells are picked from the available overlaps, and outline shimmer.

This follows the parent doc's section 2.3 and `cymatic-standing-wave-algorithm-brief-2026-05-20.md` section 9. Critically, growing `ring_count` never produces wallpaper: the renderer still caps visible cells at `density_cap` regardless of how many construction rings exist (section 6.3). More rings = more candidate overlaps; the same sparse phrase renders.

### 1.5 Resolume / MIDI knobs -> operator parameters

Layer 3, direct writes, highest priority. Each operator control binds to one CSPV field:

| Control | CSPV field | Range | Effect |
|---|---|---|---|
| Construction-circle opacity | `construction_circle_opacity` | 0.0-1.0 (operate 0.0-0.2) | Fades the hidden generator circles up for a brief "reveal the geometry" moment. Default 0.0 - circles stay hidden. |
| Fill / line inversion | `line_fill_balance` | 0.0 (all outline) - 1.0 (all fill) | Static bias of the outline-vs-fill display state without touching field topology. |
| Growth speed | `growth_rate` | 0.0-1.0 | Overrides the audio-driven ring growth rate. |
| Cell density | `density_cap` | 8-24 | How many emergent cells render. |
| Snow depth | `snow.snow_depth` | 0-120 (operate 12-80) | Count of falling snowflakes in the rectangular-fall layer. |
| Symmetry | `symmetry_order` | 0-8 | Overlap symmetry of the arrangement. |
| Ring count | `ring_count` | 0-5 | Construction rings (seed vs flower). |
| Mode selector | `mode` | 5 enums | Topology-cell mode. |
| Blackout / panic | kill-switch -> fallback scene | momentary | Drops the topology-cell layer instantly. |

Operator writes clamp any layer below them. The operator can freeze any field, and the panic button is the section 5 kill-switch.

## 2. MVP Interactions

Three interaction modes for IMPACT (May 27-28, HR MacMillan Space Centre). All three are plumbing; the cymatic visual content they drive is Austin-review-gated (section 5, and parent doc section 7).

### 2.1 Auto-cycle topology-cell loops (Layer 0)

The floor. A deterministic clock steps through the five topology-cell modes - `seed` -> `snow` -> `sun` -> `water_ripple` -> `network` -> back - every ~90-120 s, each step on a fixed seed. With nothing else running this produces a complete, reproducible show. Renderer path A (today) cross-fades the pre-rendered v002 topology-cell loops in Resolume; path B (later) runs the deterministic generator per mode. This is also the IMPACT-safe default given the content gate.

### 2.2 Operator controls mode + intensity in Resolume (Layer 3)

Pravin or Darren at Resolume + a MIDI controller selects the `mode` and drives one **intensity macro** plus the section 1.5 knobs. The intensity macro is a single fader bundling `growth_rate`, `phase_inversion_intensity`, and `wave_strength` so the operator can move the whole field from calm to active without chasing individual parameters. Mode selector, kill-switch, and opacity are always live. This is the lowest-risk input to wire - native Resolume + MIDI, already core to the gallery stack.

### 2.3 Optional web prompt selects a template, not AI-generated art (Layer 2)

A visitor scans the QR code, opens `web/visitor.html`, types a short phrase. The phrase's **only job is to select one of the five topology-cell templates** (mode presets). It does not generate art, does not call a model on the live path, does not produce novel imagery. The local keyword classifier maps the phrase to a `mode` and a small set of preset CSPV fields; an unknown or unsafe phrase falls back to a safe template (`network` or `seed`). Optional async enrichment may refine `palette`/`energy` into a *future* CSPV only - it never blocks or alters the scene on the wall. This preserves the project's no-AI-generation posture: the system arranges deterministic topology cells from a fixed template library, never free-generates.

## 3. Five Concrete Interaction Scenarios

Each traces input -> resolution -> CSPV -> renderer -> wall.

### 3.1 "snow falling over water"

1. Visitor types "snow falling over water"; raw text -> local dream gateway only.
2. Classifier matches "snow" + "water": a two-layer scene. Base = a calm water layer (`ocean`/`water_ripple` loop or clean Moonfish water footage on a lower Resolume layer). Top = a `snow` topology-cell layer.
3. CSPV for the topology-cell layer: `mode: snow`, `field_family: csg_seed`, `layout: rectangular_fall`, `snow: {snow_depth: 48, fall_speed: 0.35, flake_symmetry: 6}`, `energy: calm`, `palette: pale_cyan_on_black`, `cell_classes_shown: [circle, crescent, trigon]`.
4. Renderer: the snow rectangular-fall layer composites (Screen/Add) over the water base. Many small sixfold topology snowflakes drift down the rectangular frame; the water moves beneath.
5. Today's fallback: the rectangular falling-snow layer is a recommended next render, so the centered `03_snowflake_harmonic` v002 loop stands in over the water base until the rectangular layer exists.
6. Wall: snow topology-cells falling over moving water; quiet, layered, deep.

### 3.2 "sun after rain"

1. Visitor types "sun after rain" - a temporal sequence.
2. Classifier resolves a two-phase scene. Phase 1: `water_ripple`, `energy: calm`, decaying. Phase 2: cross-fade to `sun` emerging.
3. CSPV sequence: CSPV A (`mode: water_ripple`, `emitter_count: 5`, `wave_strength` decaying) then CSPV B (`mode: sun`, `field_family: bessel`, `symmetry_order: 6`, `brightness` rising, `cell_classes_shown: [circle, crescent, trigon]`).
4. Renderer: water_ripple overlap-cell interference calms and fades; a central circle/origin orb brightens and releases radial crescent phase arcs and trigon ray cells. Path A cross-fades two pre-rendered loops; path B interpolates `mode` in the generator.
5. Wall: ripple interference settling into a radiant field. Abstract radial topology only - no exact Austin sun replication.

### 3.3 "flower of life ripple"

1. Visitor types "flower of life", or the operator selects it.
2. Classifier: `mode: seed`, `ring_count: 3` (flower-of-life), `layout: radial`.
3. CSPV: `mode: seed`, `field_family: csg_seed`, `ring_count: 3`, `growth_rate: 0.45`, `phase_inversion_intensity: 0.5`, `cell_classes_shown: [crescent, trigon]`, `construction_circle_opacity: 0.05`, `symmetry_order: 6`.
4. Renderer: the seed-overlap generator adds rings of construction circles outward over time; a phase-inversion wave sweeps radially so emergent crescents and trigons fill, then invert, ring by ring. Construction circles stay near-invisible.
5. Wall: a flower-of-life field where the visible layer is crescents and trigons emerging from overlaps and a ripple of fill sweeping outward - explicitly not circles with icons placed on top.

### 3.4 "mist network"

1. Visitor types "mist", "network", or "everything connected".
2. Classifier: `mode: network`, sparse and faint.
3. CSPV: `mode: network`, `field_family: multi_emitter`, `density_cap: 9` (low), `brightness: 0.3`, `construction_circle_opacity: 0.0`, `energy: calm`, `cell_classes_shown: [circle, crescent, trigon]`.
4. Renderer: a weak field yields a sparse node/edge/cell graph - faint circle nodes, crescent edges along the graph, occasional trigon releases at terminal confluences.
5. Wall: an atmospheric topology network with large quiet negative space; density comes from a few events, never from filling the frame.

### 3.5 Touch-triggered impact origin

1. A visitor taps the touchscreen at `(x, y)`.
2. The CSPV appends `impulse {x, y, amp: clamp(0.4 + 0.5*s), ttl_s: 4.0, kind: "origin"}`. A tap near an existing origin promotes to `kind: "ring"`.
3. Renderer: a new construction-circle origin (or ring) appears at `(x, y)`; its overlaps with the existing arrangement generate fresh crescents and trigons at the new intersections; the cells bloom, then settle as `ttl_s` expires.
4. Rate-limited to ~3/s, max 12 active impulses; excess taps dropped.
5. True live origin injection needs the TouchDesigner realtime generator stable. Degraded IMPACT version: a tap triggers a short pre-rendered "origin bloom" clip instead of live injection.

## 4. Offline Fallback Behavior

The system must run a complete, beautiful show with no internet, no audio, no visitor, and no operator. Only Layer 0 is required.

- **Layer 0 deterministic auto-cycle** steps through `seed` -> `snow` -> `sun` -> `water_ripple` -> `network` every ~90-120 s, each step on a fixed PRNG seed. The cycle is fully reproducible - the same wall every run.
- **Renderer path A (today):** Resolume cross-fades the pre-rendered v002 topology-cell loops. `01_seed_of_life` and `03_snowflake_harmonic` lead the cycle. `02_rain_on_water_interference` and `04_cymatic_nodal_plate` are demoted - they read as too crude, so they are not given hero auto-cycle slots; they remain available only as internal reference. The water/ripple slot uses the gentler overlap-cell `water_ripple` treatment once a suitable loop is rendered.
- **Renderer path B (later):** the deterministic generator (`scripts/cymatic_standing_wave_phase_inversion_v002.py` lineage) runs each mode on its fixed seed - pure NumPy/OpenCV field math, zero network.
- **The topology-cell layer sits on its own Resolume layer group**, above the clean Moonfish/Evan water footage of the MVP fallback package (`mvp-fallback-resolume-package-2026-05-19.md`), blend Screen/Add, low opacity. On any renderer failure or heartbeat loss, the layer auto-fades and that fallback floor carries the wall.
- No clock, no seed dependency on anything external. This layer is the floor; it has no fallback because it has no dependency.

## 5. Safety / Cultural Boundary

This document inherits every boundary from its sibling docs in this lane.

- **Internal only.** Interaction/input design, not a public specification. Nothing here authorizes a public showing.
- **No Austin-approval claims.** The v002 cymatic packet this drives is `INTERNAL ONLY. Austin-review-needed`. Ready plumbing does not make content public-safe.
- **Web prompt selects a template; it never generates art.** No model runs on the live path. The system arranges deterministic topology cells from a fixed library. Async enrichment may only refine a future CSPV, never the live wall.
- **Visitor prompts must not generate named chiefs or specific people.** The classifier blocks named people, chiefs, living public figures, and portraits - no render, hold on the auto-cycle.
- **Block supernatural / crest beings from the live path.** Thunderbird, double-headed serpent, Transformer, crest, clan, ceremony, ancestor, named beings - blocked from live visitor rendering; an operator may log them for a later Austin conversation only.
- **Abstract topology only.** Circles, crescents, trigons, nodal lines, overlap cells - boundary-relation topology. No fish/bird/wing/fin/eye/face semantics. Watch that clustered origin circles do not read as eyes or roe.
- **No exact Austin source replication.** No mode, prompt, or knob may reproduce Austin's salmon, raven, sun, or other source-piece geometry, palette, or atom adjacency.
- **No "sacred geometry" as authorization.** Seed-of-life and flower-of-life are used here only as circle-overlap topology. Project language is "circle-overlap topology", "cell extraction", "internal primitive grammar sketch" - never "sacred geometry", "Austin's style", or "Coast Salish style".
- **Audio reactivity is not cultural translation.** Driving the field with sound is internal math/design; it must never be framed as translating sound into approved cultural grammar.
- **The topology-cell layer has its own kill-switch** - `/cymatic/blackout 1`, a MIDI panic button, or a Resolume layer-group solo-mute - separate from any Austin-derived asset group, so it can be removed from the wall in one action.

## 6. Recommended `cymatic_scene.v1` Fields for Topology Cells

The CSPV stays `cymatic_scene.v1`. The topology-cell fields are **additive with safe defaults**, so a resolver that ignores them still produces a valid scene. The renderer remains the only consumer; raw input never reaches it.

### 6.1 Updated vector

```json
{
  "schema_version": "cymatic_scene.v1",
  "mode": "seed|snow|sun|water_ripple|network",
  "field_family": "csg_seed|multi_emitter|bessel",
  "layout": "radial|rectangular_fall",
  "ring_count": 2,
  "growth_rate": 0.4,
  "construction_circle_opacity": 0.05,
  "cell_classes_shown": ["circle", "crescent", "trigon"],
  "symmetry_order": 6,
  "phase_inversion_intensity": 0.5,
  "line_fill_balance": 0.5,
  "density_cap": 14,
  "emitter_count": 5,
  "wave_strength": 0.5,
  "expansion_speed": 0.5,
  "phase_speed": 0.4,
  "brightness": 0.6,
  "palette": "pale_cyan_on_black",
  "energy": "calm|neutral|intense",
  "snow": { "snow_depth": 48, "fall_speed": 0.35, "flake_symmetry": 6 },
  "impulses": [{"x": 0.5, "y": 0.5, "amp": 0.8, "ttl_s": 4.0, "kind": "origin"}],
  "seed": 313,
  "cultural_status": "internal_austin_review_needed"

```

### 6.2 New fields

| Field | Type | Bounds (default) | Layers that write | Purpose |
|---|---|---|---|---|
| `layout` | enum | `radial` \| `rectangular_fall` (`radial`) | 0, 2, 3 | Centered field vs the rectangular falling-snow layer. |
| `ring_count` | int | 0-5 (1) | 0, 1 (low band), 2 (touch), 3 | Hex rings of construction circles. 0 = center only, 1 = seed-of-life, 2+ = flower-of-life. |
| `growth_rate` | float | 0.0-1.0 (0.35) | 0, 1 (amplitude), 3 | How fast new construction rings are added. |
| `construction_circle_opacity` | float | 0.0-1.0, operate 0.0-0.2 (0.0) | 3 | Visibility of the hidden generator circles. Default hidden; a brief operator "reveal" only. |
| `cell_classes_shown` | array, subset of `[circle, crescent, trigon, network]`, non-empty | (`[circle, crescent, trigon]`) | 2, 3 | Which emergent cell classes render. Use `[crescent, trigon]` to keep circles hidden. |
| `phase_inversion_intensity` | float | 0.0-1.0 (0.5) | 0, 1 (amplitude), 3 | Strength of the outline -> fill -> inverse-fill swap (grammar doc 4A). |
| `snow.snow_depth` | int | 0-120, operate 12-80 (48) | 0, 3 | Count of falling snowflake units. Meaningful only when `layout: rectangular_fall`. |
| `snow.fall_speed` | float | 0.0-1.0 (0.35) | 0, 1, 3 | Vertical drift speed of the snow layer. |
| `snow.flake_symmetry` | int | 4-8 (6) | 0, 3 | Internal symmetry of each snowflake unit. |
| `impulses[].kind` | enum | `origin` \| `ring` \| `ripple` (mode default) | 2 | What a touch impulse seeds. Topology-cell modes default to `origin`; `water_ripple` defaults to `ripple`. |

`mode` gains `seed` and `water_ripple` as enum values; legacy `rain` is coerced to `water_ripple`, legacy `mist` to `network`. `field_family` for the topology-cell modes is `csg_seed` (seed, snow), `multi_emitter` (water_ripple, network), or `bessel` (sun).

### 6.3 Bounds and validation

Inherited hard bounds, enforced before the renderer sees the vector: `emitter_count` 3-7, `symmetry_order` 0-8, `density_cap` 8-24, all `*_strength`/`*_speed`/`brightness`/`line_fill_balance` floats clamped 0.0-1.0, `impulses` capped at 12 active.

Topology-cell validation, fail-closed - the renderer rejects or coerces before drawing:

- Out-of-bounds numeric fields are clamped; an empty `cell_classes_shown` is rejected and the scene falls back to the previous valid CSPV.
- **Ring growth never becomes wallpaper.** Visible cells are always capped at `density_cap` regardless of `ring_count` - more rings means more candidate overlaps, never more rendered cells. This enforces the tiling doc's sparse-phrase rule.
- `construction_circle_opacity` above 0.2 is permitted by the schema but flagged as an operator-only "reveal" state - it is never a default or a preset value.
- `mode: snow` with `layout` other than `rectangular_fall` is coerced to `rectangular_fall`; the `snow` object is ignored for every other mode.
- `cultural_status` is fixed at `internal_austin_review_needed` and may not be overridden by any input layer.

### 6.4 OSC additions

New OSC addresses, siblings of the parent doc's section 4.3 table, carried by a bridge modeled on `scripts/bioregional_osc_bridge.py` and the `live-feed-osc-contract.md` conventions (raw values; TD smooths locally; heartbeat so the layer never drops to black):

| OSC address | Type | Meaning |
|---|---|---|
| `/cymatic/layout` | int | 0 = radial, 1 = rectangular_fall |
| `/cymatic/ring_count` | int | 0-5 |
| `/cymatic/growth_rate` | float | 0.0-1.0 |
| `/cymatic/construction_opacity` | float | 0.0-1.0 |
| `/cymatic/phase_inversion` | float | 0.0-1.0 |
| `/cymatic/snow_depth` | int | 0-120 |
| `/cymatic/snow_fall_speed` | float | 0.0-1.0 |
| `/cymatic/impulse` | float x3 + int | x, y, amplitude, kind (0 origin / 1 ring / 2 ripple) |

`cell_classes_shown` is set by discrete mode/preset selection or a control DAT, not a single OSC float; `snow.flake_symmetry` rarely changes live and is set per preset. Raw prompt text is never an OSC value - the gateway resolves a prompt to CSPV fields before anything reaches OSC/TD.
