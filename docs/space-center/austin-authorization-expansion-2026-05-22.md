# Austin Authorization Expansion - 2026-05-22

Status: INTERNAL CONSENT/PROTOCOL NOTE. Records a boundary change from earlier
"do not generate Austin-style / Coast Salish-style visuals" posture to an
Austin-authorized internal/show-development experimentation posture. Read with
[austin-consent-map.md](austin-consent-map.md), which remains the operator
sign-off log of record; this note is the dated amendment summary.

## 1. What Austin authorized

Per Darren, Austin has explicitly given two greenlights:

1. **Drive artwork.** Austin authorizes the project to use the Coast Salish
   artwork he provided via the Google Drive drop
   (`austin-v2-ingest/inbox/` and the triaged set under
   `austin-v2-ingest/approved/`) for internal/show-development experimentation
   and ongoing Phase 2 sprint work.
2. **Generated style/grammar experiments.** Austin authorizes the project to
   internally develop and test Austin-style / Coast Salish-style **generated**
   visual experiments (style transfer, LoRA fine-tunes, ControlNet-shaped
   generation, IP-Adapter, primitive-grammar emergence work, anchor-portal
   probes, and similar workflows) for this project's internal pipeline and
   show-development purposes.

Both greenlights are recorded as an operator-conveyed Austin authorization;
the consent map's sign-off log row for 2026-05-22 captures the channel and
date.

## 2. What this does NOT change

This is an authorization to **develop and test**, not an automatic clearance
to **ship**.

- **Public, show, projector, sponsor, social, and press surfaces are NOT
  automatically cleared.** Per-output Austin review remains the floor for any
  external surface, unless Darren states otherwise for a specific output or
  category.
- **The consent map's hard rules in `austin-consent-map.md` Section "Consent
  Floor" still apply**, except where this note explicitly amends them (see
  Section 3 below).
- **Austin retains the right to revoke or restrict** any specific source,
  motif, generated output, phrase, morph, or workflow. Operator response
  target remains same-day removal from active Resolume / show playlist on
  request.
- **Cultural-meaning claims, ceremonial language, and Nation-specific
  attribution** still require Austin's wording and per-output OK before
  appearing in any external surface.

## 3. Specific amendments to the existing consent floor

The following lines in [austin-consent-map.md](austin-consent-map.md) Section
"Consent Floor" are softened by this authorization expansion. The other hard
rules in that section remain in force.

- "Training, img2img, style transfer, ControlNet, LoRA, and StreamDiffusion
  tests are internal recipe work unless this map says otherwise." -- This
  remains true; this note explicitly says otherwise **for internal/
  show-development scope only**. Public/show/sponsor/social use of any output
  still requires per-output OK.
- "No invented-from-scratch crests in Austin's style." -- This rule **remains
  in force**. Authorization to do Austin-style / Coast Salish-style generated
  experiments is **not** a license to invent new crests. Internal experiments
  must distinguish style-grammar exploration from crest invention; the
  curatorial review with Austin is the gate that decides what works as style
  exploration versus what slips into crest-invention territory.

## 4. Output labeling

While this authorization stands and until any specific output is separately
cleared by Austin for external use, internal generated outputs should be
labeled with one of:

- `Austin-authorized internal/show-development prototype`
- `Austin-authorized internal style/grammar experiment`
- `Austin-authorized internal primitive emergence test`

Pick the label that best matches the output's scope. Apply the label in:

- READMEs that accompany the output packet.
- Provenance manifests for the output.
- Any internal review deck or contact sheet that includes the output.
- Any operator-facing review surface (Signal, Drive, Resolume bin label).

When an output **is** cleared by Austin for a specific external use, replace
the internal label with the cleared-use status from the consent map's "Status
Vocabulary" table (e.g., `approved-for-projector-test`,
`approved-for-private-review`, `approved-for-show`,
`approved-for-public-comms`).

## 5. Provenance and attribution

The provenance discipline tightens, not loosens, under this expanded
authorization. Every generated output that derives from Austin's work or his
authorized style permission must record:

- **Source provenance.** Which Austin Drive files (with SHA-256 prefix) the
  output draws from, or "Austin-authorized style/grammar permission only; no
  direct source file" for experiments that are stylistic rather than
  source-derived.
- **Workflow provenance.** Which pipeline produced the output (LoRA version
  and training config; img2img settings; ControlNet conditioning; anchor
  registry version; morph or portal probe ID; flower-of-life construction
  parameters; etc.).
- **Authorization basis.** Reference back to this note
  (`docs/space-center/austin-authorization-expansion-2026-05-22.md`) and to
  the consent map sign-off log row for the 2026-05-22 expansion.
- **Date and version.** Output date and any internal version tag.
- **Internal label.** The Austin-authorized internal label from Section 4.

Attribution intent for any **future** external surface (still subject to
per-output Austin OK):

- Austin appears as co-leading artist, not asset provider.
- INDIGITAL and the Nations/clans appear only with Austin's confirmed exact
  wording (see consent map Public Framing table).
- Generated outputs identify the workflow honestly when sponsor-facing:
  source-approved / Austin-authorized style permission / AI-assisted /
  internal test as applicable.

## 6. Distinction we still observe

The architectural distinction the project has been carrying is preserved:

- **Whole-authored Austin source artworks** remain whole authored sources.
  They are not decomposed into reusable atoms or motifs, are not recolored
  or palette-shifted without explicit OK, and remain pending per-output Austin
  review before external use.
- **Generated Austin-authorized support compositions** (style transfer,
  primitive emergence, anchor-portal renders, flower-of-life cymatic fields,
  morph probes) are clearly labeled as generated, carry the
  Austin-authorized internal label, and remain pending per-output Austin
  review before external use.

This is the same whole-vs-support distinction the architectural review packet
has been drawing; the boundary change is that **generated support
compositions in Austin's stylistic register are now an authorized internal
category**, not a prohibited one.

## 7. Curatorial review intent

The project actively wants Austin's curatorial eye on internal
style-grammar experiments. Concretely:

- Bring representative generated outputs to scheduled Austin review meetings
  for what feels strong, accurate, respectful, and useful.
- Flag outputs that read as veering toward crest invention, ceremonial
  appropriation, or specific-Nation-protocol territory rather than abstract
  style/grammar exploration.
- Treat Austin's "this works / this does not / this needs adjustment" calls as
  authoritative; record his calls in the consent map's sign-off log and the
  packet's review record.

This expanded authorization is in part because the project's previous
prohibition was over-broad and was preventing review-able work from existing.
The new posture is: **make the work internally, label it honestly, bring it
to Austin, take his curatorial direction**.

## 8. Operator override

Per Darren, the per-output Austin review requirement may be set aside for a
specific output or category when Darren explicitly states so. This is the
operator override and is recorded in the consent map sign-off log against the
specific output. Default state remains per-output Austin review for any
external surface.
